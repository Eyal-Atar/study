# ארצ׳י (StudyFlow)

> 🚧 **האפליקציה עדיין בהקמה.** היא לא פתוחה למשתמשים, אבל אפשר לראות איך היא תיראה:
> **[לדמו של ארצ׳י](https://eyal-atar.github.io/study/)**

## מה היא אמורה לעשות

ארצ׳י עוזרת לסטודנטים להתכונן למבחנים. מעלים את חומרי הקורס (סילבוס, סיכומים ובעיקר מבחני עבר), אומרים מתי המבחנים ומתי יש זמן פנוי, ומקבלים תוכנית לימודים יומית שמתעדכנת לבד:
- אם פספסתי יום, התוכנית מסתדרת מחדש בלי לשבור את כל השבוע.
- אף משימה לא נעלמת בשקט: מה שלא נכנס ללוח מופיע ברשימה עם הסבר למה.
- אפשר לצלם את מערכת השעות, והאפליקציה מבינה ממנה מתי אני תפוס.
- ארצ׳י, הדמות של האפליקציה, מלווה את ההתקדמות עם נקודות, רצפים ותגים.

## איפה הפיתוח עומד

- **מוכן:** השרת והליבה: התחברות, קליטת חומרים וניתוח שלהם עם AI, בניית התוכנית ושינוי שלה, מסכי היום, השבוע והמבחנים, סקירת בוקר, גרירת משימות, נקודות ותגים, וסגירת מבחן ומועד ב׳.
- **עכשיו:** תצוגת לוח שנה, נגישות, והמסכים שנשארו.
- **הבא:** בדיקה על טלפונים אמיתיים, ואז משתמשים ראשונים.

## איך זה בנוי, בקצרה

- **`web/`**: האפליקציה שהסטודנט רואה. React עם TypeScript, מותאמת קודם כול לטלפון ואפשר להתקין אותה כמו אפליקציה.
- **`api/`**: השרת, ב־Python עם FastAPI. כאן נמצא המתכנן, החלק שמחליט מה ללמוד ומתי.
- **מסד הנתונים וההתחברות**: Supabase ‏(PostgreSQL). כל סטודנט רואה רק את הנתונים שלו, וזה נאכף במסד עצמו.
- **ה־AI**: ‏Claude קורא את חומרי הקורס ומפרק אותם לנושאים. יש סט בדיקות קבוע (`api/eval/`) שבודק שהתוצאות לא הידרדרו.
- **בדיקות**: כל שינוי עובר בדיקות אוטומטיות ב־GitHub לפני שהוא נכנס, יותר מ־1,000 בדיקות לשרת ומאות לאפליקציה.

## למפתחים: איך מריצים

## הרצת ה-API

הפקודות רצות מתוך `api/`, וצריך [uv](https://docs.astral.sh/uv/). לבדיקות צריך גם Postgres 17 מקומי (`brew install postgresql@17 && brew services start postgresql@17`).

```bash
cd api
uv sync
cp .env.example .env    # וממלאים את SUPABASE_URL ואת MIGRATION_DATABASE_URL
uv run alembic upgrade head
uv run uvicorn app.main:create_app --factory --reload
```

בדיקות: `uv run pytest` (הן יוצרות מסד `studyflow_test` ב-Postgres המקומי). lint ופורמט: `uv run ruff check .` ו-`uv run ruff format --check .`. טיפוסים: `uv run mypy`.

## הרצת ה-worker

ה-worker הוא תהליך נפרד שמריץ את העבודות שבתור (למשל קליטת חומר שהועלה). הוא רץ מתוך `api/`:

```bash
cd api
uv run python -m app.jobs
```

הוא קורא את אותן הגדרות כמו ה-API, ובנוסף שני משתנים ב-`.env`: ‏`WORKER_DATABASE_URL` (חיבור כבעלים של הסכמה) ו-`SUPABASE_SECRET_KEY` (גישה ל-Storage). שני המשתנים האלה שייכים ל-worker בלבד: ה-API לא משתמש בהם, ובסביבת production מגדירים אותם רק לתהליך של ה-worker.

## הרצת ה-web

הפקודות רצות מתוך `web/`, וצריך Node 24 עם npm 11.17 ומעלה.

```bash
cd web
npm ci
cp .env.example .env    # וממלאים
npm run dev
```

ה-API צריך לרוץ, ו-`CORS_ORIGINS` שלו צריך לכלול את `http://localhost:5173`.
