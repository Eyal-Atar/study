   - Track current exam index (0-based) relative to `draft.examCount`
   - `updateExamLoopUI(currentIndex, totalCount)` function:

   - Call `updateExamLoopUI()` on step 1 entry and after each exam save

7. Wire `#onb-next-exam` button onclick:
   - Save current exam to `draft.exams[]`
   - If more exams remain: clear form fields, reset file list, increment exam index, call `updateExamLoopUI()`
   - If this is the last exam: trigger `submitOnboarding()`

8. Wire `#onb-skip-remaining` button onclick:
   - Save current exam if it has at least a name AND a date filled
   - Submit whatever exams have been collected so far via `submitOnboarding()`

9. Update `setStep()` to skip step 2 entirely (since merged into step 1). After step 1, the flow goes directly to submission. Remove or guard any `setStep(2)` calls. Update the step counter display to not count the eliminated step.

    - On dragleave/drop: remove `.dragover` class

    - Show a green checkmark (✅ or `<span class="text-green-500">✓</span>`) next to the filename after successful upload

<task type="auto">
  <name>Task 2: Implement personalized dynamic loading overlay</name>
  <files>frontend/js/onboarding.js</files>
  <action>
1. Add `buildLoadingMessages(courseNames)` function that takes an array of course name strings and returns an array of `{ percent, text }` objects:
   - `{ p: 5, t: "Decoding the files you uploaded..." }`
   - For each course name: `{ p: 15 + (i * 15), t: "Reading the syllabus of {name}..." }`
   - `{ p: 70, t: "Detecting knowledge gaps and tricky questions in {lastCourseName}..." }`
   - `{ p: 85, t: "Scheduling strategic reviews based on your study windows..." }`
   - `{ p: 95, t: "Assembling your final action plan..." }`
   - Ensure percentages are capped at 95 and don't overlap. If many courses, compress the per-course messages to fit.

2. In `submitOnboarding()`, BEFORE calling `clearDraft()` or the API:
   - Capture `const courseNames = draft.exams.map(e => e.name).filter(Boolean)`
   - Build messages: `const messages = buildLoadingMessages(courseNames)`

3. After showing the loading overlay (`showModal('loading-overlay', true)` or equivalent):
   - Set up a `setInterval` (2500-3000ms) that cycles through the messages array
   - On each tick: update `#loading-status-text` (or `#loading-text`) with the current message text, update any progress bar with the percent value
   - Apply the existing `status-fade` CSS class for smooth text transitions (remove class, force reflow, re-add class)
   - Store the interval ID in a module-level variable so it can be cleared

4. When the API call completes (success or error):
   - `clearInterval()` on the stored interval ID
   - Proceed with existing success/error handling

5. Add a subtle wave/scanner visual to the loading overlay. In the HTML (or dynamically via JS), add an animated element above the text. Use CSS animation only (no library). Options:
   - A pulsing brain emoji with scale animation
   - Or a simple CSS wave using `@keyframes` with opacity pulses on 3-4 dots/bars
   - Keep it minimal — the cycling text is the main attraction

**Race condition prevention (from RESEARCH Pitfall 3):**
- `courseNames` must be captured into a closure variable BEFORE any async operation or draft clearing
- The interval callback references the local `courseNames` and `messages` variables, NOT `draft`
